# הצעה: שירות "הסכם פתיחת מצבה" – לינק לחתימה דיגיטלית

## Context – למה ומה

כשמשפחה מבקשת לפתוח מצבה קיימת (מצבה כפולה, הנפטר השני) ואז עוברת לספק אחר לכתיבה,
העבודה שלי (פתיחה) לא משולמת. הפתרון: **לפני** שאני פותח, הלקוח חותם דיגיטלית על התחייבות לשלם
סכום מוגדר ועל תנאים. תהליך קצר:

1. אני מזין סכום (+ שם/טלפון/פרטי המצבה) ומקבל **לינק ייחודי**.
2. שולח בווטסאפ.
3. הלקוח פותח את הלינק, רואה סכום ותנאים, מזדהה וחותם.
4. אני מקבל התראה + PDF חתום, ורק אז פותח.

## המלצה קצרה

| שאלה | המלצה |
|---|---|
| לעשות בתוך פרויקט האתר? | **לא בתוך האתר. אפליקציה נפרדת באותו workspace** (תיקייה `agreements/` ליד `frontend/`), פרויקט Vercel נפרד, תת-דומיין (למשל `sign.alper-marble.co.il`) |

| מסד נתונים? | **כן, חובה** (Postgres – Neon/Supabase חינמי). הסכם חתום הוא ראיה, חייב להישמר |

## למה לא בתוך האתר הקיים

- האתר הציבורי הוא סטטי, בלי DB, בלי auth (`.doc/architecture.md`). הסכמים חתומים הם **מידע אישי ומשפטי**
  – לא רוצים לערבב עם קוד שמתעדכן בתדירות גבוהה של תוכן/תרגומים.
- הדפלוי של האתר חי ב-alper-marble.co.il; באג בשירות החדש לא אמור להפיל את האתר ולהפך.
- סודות נפרדים (DB, SMS, מפתחות חתימה) – הפרדה מצמצמת סיכון.
- אתה אמרת בעצמך שזה לא חלק מהאתר. אפליקציה נפרדת שומרת על זה נקי, ועדיין **אותו workspace** =
  אותם כללי קוד (`.rule/`), אותו agent, אפשר לשתף קטעי קוד.
- נוח להתחיל מקומית (`localhost`) ולהעלות רק כשמוכן.

> אפשרות חלופית (פחות מומלץ): route group בתוך `frontend/` עם `noindex`. מהיר יותר, אבל מכניס DB ו-auth
> לאתר הציבורי ומחייב עדכון ארכיטקטורה/מדיניות. עדיף נפרד.

## למה Next.js אחד ולא React + Node

- Route Handlers של Next = Node.js. אותה שפה (TS), פריסה אחת, בלי CORS, בלי שרת לתחזק.
- אתה כבר מכיר את הסטאק מהאתר (Resend, Vercel, next-intl).
- Express נפרד שווה רק אם צריך תהליכי רקע ארוכים – כאן לא.
- RTL/עברית – כבר פתור באתר, ניתן להעתיק.

## זרימה (Flow)

```
[אני] עמוד יצירה (מוגן סיסמה)
   קלט: סכום, שם הלקוח, טלפון, תיאור (מצבה/בית עלמין/מי הנפטר), תוקף
   ↓ נוצר רשומה + טוקן אקראי (128 ביט)
   ↓ מקבל לינק: https://sign.…/s/<token>   + כפתור "שלח בווטסאפ" (wa.me/?text=…)
[לקוח] פותח לינק (מובייל)
   רואה: סכום, תנאים, פרטי העבודה
   ממלא: שם מלא, ת"ז, מסמן "קראתי והסכמתי", חותם באצבע (canvas)
   אימות: קוד SMS חד-פעמי לטלפון שהזנתי (OTP)
   ↓ נשמר: חתימה, IP, user-agent, זמן, hash של נוסח התנאים
[מערכת]
   מייצרת PDF חתום, שולחת לי מייל (Resend – כבר קיים) ללקוח עותק
   הסטטוס בעמוד שלי: נוצר → נפתח → נחתם
```

## מודל נתונים (מינימלי)

`agreements`: id, token_hash, amount_ils, client_name, client_phone, job_description,
terms_version, status (`created|viewed|signed|expired|cancelled`), expires_at, created_at

`signatures`: agreement_id, signer_name, signer_id_number (מוצפן), signature_image,
signed_at, ip, user_agent, otp_verified_at, terms_text_hash, pdf_url

`terms_versions`: version, text, hash – כדי להוכיח **איזה נוסח** נחתם.

שומרים בצד השרת רק hash של הטוקן; לינק חד-פעמי לחתימה, פג תוקף אחרי X ימים.

## תנאים משפטיים וחתימה אלקטרונית (חשוב)

- בישראל חתימה אלקטרונית "רגילה" (תמונת חתימה + אימות) מקובלת כראיה להסכם, אבל **חוזק הראיה** תלוי בנסיבות.
  מחזקים עם: אימות טלפון OTP, ת"ז, IP+זמן, hash של הנוסח, PDF שמור. חתימה "מאושרת" (תעודה דיגיטלית) – מיותרת כאן.
- **נוסח ההסכם צריך לעבור עורך דין** (פעם אחת). זו ההשקעה הכי חשובה – הקוד הוא החלק הקל.
- נקודות לנוסח: סכום ברור, מע"מ, מועד תשלום, ביטול, מי חותם (קרוב משפחה כאחראי לתשלום), מה כולל "פתיחה".
- פרטיות: לאסוף מינימום (שם, ת"ז, טלפון). לא להציג בלינק פרטי נפטרים מעבר לנחוץ. הגדרת מחיקה אחרי X שנים.
- הלינק: `noindex`, בלי מידע רגיש בלי טוקן, rate limiting על ניסיונות OTP.

## סטאק מוצע

- Next.js (App Router) + TypeScript + TSX, RTL
- Postgres (Neon) + Drizzle/Prisma
- SMS OTP: ספק ישראלי (Twilio / Inforu / 019) – **החלטה פתוחה**
- PDF: `pdf-lib` או `@react-pdf/renderer`, אחסון ב-Vercel Blob (פרטי)
- מייל: Resend (קיים)
- Auth ליוצר: סיסמה אחת ב-env + cookie חתום (בלי משתמשים/הרשמה)
- בדיקות לפי `.rule/testing-rules.md`
